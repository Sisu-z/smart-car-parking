# 从方向判断到工程落地（案例驱动）

本技能处理一整段尚未定型的工程过程：已知大致方向或项目要求，但**细分做什么、采用哪类技术路线都可能尚未决定**；先判断哪些方向值得做、哪些路线有希望做成，再推进可验证的实现。不能把“有大方向”误读成“具体方案已定”，也不能把方案比较当成交付完成。案例是证据与可复用资产的入口，不是答案库。

## 何时使用

- 只有大方向/项目要求：探索若干有区别的**细分成果**，例如最终要展示哪种可观察能力；再比较每种成果可能的技术路径。
- 成果形态大致清楚、技术路径未定：保留成果要求，比较替代架构、现成基础和关键依赖，不直接跳到写代码。
- 路线暂定、实施卡住或准备交付：验证假设、复用基线、整体验收；新证据推翻路线时回到候选比较。

用户确认的上层要求是边界；细分成果、技术路线和实现细节是不同层次的可变决定。只有足够证据支持的那一层才暂时收敛，未定的层次保留备选。简单问题直接回答，不机械执行整套流程。

## 四个核心判断

1. **现实中能否反复测试。**从方向筛选时就把“能做”落到场地、设备、时间、人手、成本和验收环境；问日常多久能获得一次有效反馈。一次演示成功不等于具备稳定迭代条件。来源示例：[C01 Cornell Segway](references/casebook.md)。
2. **什么基础可复用，何时能试完整任务。**先看已有作品实际完成了什么，区分自主、遥控、脚本、仿真及人工辅助；检查版本、接口、结构、视角、数据、许可和复现材料。能复用的直接用，必须适配的列出工作量；适当时尽早接通输入→处理/决策→执行→结果反馈。来源示例：[C02 FRC 254](references/casebook.md)。
3. **创新是否是解决瓶颈的最小改动。**从机械、传感、控制、算法、交互、测试工具中选真正影响任务结果的一处；保留可比较的原始基线。不要默认“创新”必须是更复杂的算法。来源示例：[C05 SO-101 / LeRobot](references/casebook.md)。
4. **失败是否转化为下一次判断的证据。**先测最可能推翻路线的假设；集成时核对真实环境和系统负载；保留失败记录、可回退版本与适用边界。成熟团队也会误判，关键是能据证据修正。来源示例：[C09 NUbots](references/casebook.md)。

这些是从案例归纳出的判断原则，**不是四个依次执行的阶段**；不声称所有工程师都遵守同一套固定流程。需要找先例或核对来源时阅读[案例与工程复盘](references/casebook.md)；其中的历史价格、版本和作者计划不是当前事实。

## 第一段：先判断做什么、能不能做、怎么做更有把握

1. **界定上层要求，不预填方案。**提取用户真正要求的效果、禁止项、资源与期限；把可观察结果和使用/验收场景写出来。区分“已确认要求”“偏好”“暂时设想”“未知”，不要要求用户先给完整技术规格。只追问会改变方向的缺口。
2. **并行探索成果和路线。**若细分成果还开放，找几种实质不同的完成方式；对有希望的成果再比较可信的技术实现族，只有一种可信路径时说明检索与约束，不凑数。若成果已明确，只比较路线，不擅自重新选题。优先真实作品、原作者构建记录、设计权衡、失败复盘；核对做成了什么、靠什么条件做成、哪些由人或预设完成。没有相关案例就标证据缺口，不用相似名称冒充可复用。
3. **做有边界的可行性筛查。**先排硬约束：安全、预算/工期、必需资源、场地与测试频率；再比较需求贴合度、现成基础、适配工作、关键技术成熟度、集成复杂度和首次获得有效反馈的成本。候选可标“已有依据可行 / 有条件可行 / 证据不足 / 当前不值得”；不要用无根据的百分比和精密打分。若选项优劣取决于一个未知，先不宣布胜者。
4. **用小试验区分候选。**选最可能改变方向或路线选择、且能低成本验证的假设；明确输入、环境、通过/失败标准、时间/花费上限及结果会如何改变选择。可以用实录、尺寸检查、原版软件、仿真或小样，但只声称各自实际证明的范围。输出暂定主路、备选、被排除方案及理由；证据不足时，下一步是补证据，不是凭感觉冻结设计。

## 第二段：有了暂定路线后推进工程落地

5. **拆复用与适配。**按“可直接复用 / 需适配 / 只借鉴思路 / 不宜复用”标出部件、代码和方法；核对版本、机械/电源、传感视角、接口、依赖/数据、标定、测试条件及许可。换关键前提不能叫“简单微调”。
6. **建立最小全链路基线。**尽量先运行原版或小幅适配的现成实现；记录版本、配置、人工代替环节、日志和复现步骤。一个模块能跑不等于完整任务达标。先保证安全与可回退，再做增量改进。
7. **逐项改进并交付。**每次改动声明预期收益，用相同或明确变化的测试条件比较前后结果；记录失败、人工干预、整体延迟/负载与边界。交付时冻结可复现版本，写明操作步骤、已验证范围和未解决问题。新证据否定路线时回到第一段，而不是维护一个已不成立的方案。

这是可回退的判断路径，不是要求一步做完所有研究；实际顺序由决策依赖和最大未知决定，不默认先装硬件、先写软件或先搭大平台。需要正式记录方向/路线取舍时使用[方向与落地判断卡](references/decision-sheet.md)，不强制为日常小问题填表。

## 输出与边界

处于第一段时，默认先给：**可做的细分方向、各自可能的技术路线、筛查依据、暂定建议、最关键未知和下一项区分试验**；处于第二段时，给复用边界、最小全链路基线、验证结果和下一步。涉及采购或开源复用时补充同配置增量成本、版本和许可；价格与兼容性按当前来源重核。明确“阅读过 / 编译过 / 仿真过 / 实物单次 / 实物多次”的证据等级；作者的根因猜测仍是猜测。

本技能只提供判断方法，不额外授权购买、发布、联系他人、改写主工程或启动实体设备。默认中文；若项目有现行文档或安全约束，以它们和本次用户要求为准。

**当前状态：用户要求开始推进，进入实施准备与首轮验证，不再全局暂停研发。** 总监先同步库存/执行真源、复跑已有电脑端基线、形成一个现场信息包；专业工作只有在Issue明确执行者和范围后才算派发，不冒称所有窗口已开工。工作日3～4小时、必要时周末每天8小时和实验室半天为可用容量，不预约固定日期。技术目标、E0～E5/F0～F5安全门和正式接口保持原样，不因恢复研发批准设备动作。2026-12月底交付是明确约束；12月中旬内部目标与阶段长度是条件估计，首轮证据后重估。

## 先读这半页

2026-10-19校正：已购绝缘胶带、白色磨砂10mm美纹纸、1.2m×3m黑色哑光带背胶卷材，先保留底纸试铺，详见[TRACK-V2](track_visual_spec.md)。S20F型号/X5配件/焊接耗材不重问，降压板仅待焊线。当前无确定需立即追加采购的物品，线束/保护/开关先核再定，不等于通电材料已齐。补件只看[NEXT_ACTIONS](../../NEXT_ACTIONS.md)。

- **你负责现场，Agent负责准备与分析，总监负责协调和接受。** 你不拆技术任务、不转发员工报告、不手抄测试数据，也不必先学完全部算法。现场操作和最终验收不能由生成代码替代。
- **首先用约2小时补齐断电身份/尺寸与现有相机样本。** 三类输入能同时解除电气、控制、机械、视觉和RDK的等待。不要先定制地图、买整套传感器或重搭散线面包板。
- **三条持续工作线：底盘控制、算法、RDK/系统。** 电气与机械按当前关卡参与；关键安全/接口/算法独立审查。每条线最多一个主要在制任务，不按部门凑窗口。
- **以8～10周可交付为条件目标，争取12月中旬完成。** 工作日3～4小时、周末必要时最多8小时是用户可用容量，不是必须用满的工作量；高强度联调周建议约25～30小时，等待Agent分析或配件时少排现场工作。正常采购和返工在窗口内安排，重大换型另估。
- **每次你只收到一个主测试包，最多一个不相关备用项。** 准备条件不齐就不让你到现场等代码；一个设备只有一个操作者。总监下一次被唤醒时读取结果并组织下一轮，不假定聊天关闭后会自动工作。

## 0. 现在怎样开始：画板和地图放在哪里

不是先做完所有硬件再写软件，也不是先把整张图和PCB定死。当前复用已有模块、OpenCV/回放、纯C/HAL与固定PythonRobotics，先获得可反复验证的最小底盘和真实图像。

| 顺序 | 用户主要动作 | Agent应提前交付 / 可并行项 | 这一轮结束标志 |
|---|---|---|---|
| 1. 断电信息与静态样片，约1～2h | 量车身长宽/轴距/轮径；仅补缺失版号。材料到货后在一小部分贴短直道、曲线段和U形线框，用现有USB相机拍原帧；未到货先做尺寸/相机可用性 | 电气消化现有资料和电源路径；系统准备取图/回放；算法与控制复跑已有电脑端测试。不让用户重新搬运旧照片或学完算法 | 可追溯尺寸、安装/图像与明确缺口；不是行驶许可 |
| 2. 可搬运总成与单轮台架 | 收到已审接线/测点包后固定、标号，集中实验室测量；先无执行器供电，再按关卡单轮/编码器/测速/PI | 电气出接线/保护候选与确切补件，独立Reviewer审核；控制准备固件/记录。系统和视觉继续静态回放 | 已接受对应电气及单轮证据，而不是“接上能转” |
| 3. 双轮、转向与基础行驶 | 按包测另一轮、转向、联合负载和低速停稳；测转弯/车身扫掠 | 控制闭环、系统链路及失效处理；算法先回放/影子运行，再按准入接循迹/曲线 | 可控低速底盘、可靠停止/反馈与基础道路能力 |
| 4. 地图全图与近距离泊车 | 按校核布局完成DIY贴线；多起点可见车位倒库、独立出库测试 | 用实测几何与视野定道路/车位/接近区，接入感知—规划—控制闭环 | 可见位反复成功，不宣称随机自主找位完成 |
| 5. 主动找位与交付 | 从车位不可见的不同可行起点启动；换场地、收纳复铺和故障复测 | 完善搜索/任务逻辑、失效处理、日志分析与回归；冻结交付版本 | 循迹/曲线、找位、倒库、出库和独立场地全部按既定标准验收 |

### 电路设计：现在做接线设计，PCB不挡住第一轮

- **现在要做**：电源树、信号/地线、接头/线径、保护/断电覆盖、测点与固定位置；给用户清楚的连接表/图。选用现成模块不等于不设计电路。
- **首次验证**：优先现成模块、匹配线束、可靠固定/绝缘；不要把大电流动力路径搭在散乱面包板或未核额定值跳线上。具体接法仍需审核，本节不提供未经验证的接电指令。
- **是否画板**：当模块、引脚、电压/电流路径已验证且主要问题确实是接线可靠性/体积时，可并行设计一块小型转接/配电板；有合适成品则直接复用。不要求先造整车主控板，也不要求等全部泊车算法完成才考虑板子。
- **打样前**：独立电气审查、接插件/尺寸核对和用户加工/费用确认；先保留可运行线束基线，再用新板替换复验。PCB打样不是目前已下达任务。

### 地图设计：现在开始局部与草图，不等最后一刻

- **材料到货就可做**：保留底纸试铺，在局部贴10mm样片供反光/线宽/视野检查；不贴满整卷，不把样片U形尺寸当最终车位尺寸。
- **草图可并行**：以已购1.2m×3m材料为边界，准备直道、曲线、停车位及接近区的参数化草图；标注未知转弯半径/外廓/净空。利用现有二维工具检查范围，不为此搭完整3D仿真或订制印刷。
- **全图何时定**：至少获得实测转弯/扫掠、停止余量、车位观察范围后，校核闭合路线和倒库/出库空间，再一次性铺主要布局。1.2m宽可能成为瓶颈；无解先调整布局/机动候选并向用户说明，不用缩小仿真车身掩盖。
- **交付形式**：DIY贴线可直接作为正式地图；若后续确要印刷，继承已验证的配色/线宽/净尺寸，不另定一套标准。改变布局后仍靠当次观测，不背地图坐标/动作。

### 首批并行，不同时占用你的手和设备

1. **电气/底盘线**：先接线与测点包、单轮候选；精确S20F资料、电平/电流缺口只阻塞相关通电，不阻塞软件。
2. **相机/RDK/视觉线**：现有USB相机静态原帧→离线候选叠图/误检清单；X5初检单独准备，不默认重刷TF卡。新买相机仅由实测盲区触发。
3. **算法/测试线**：复跑现有规划/控制/普通线测试；随后按任务补路径空间约束、PARK/EXIT/CANCEL与异常替身测试，不等硬件才能写，也不以仿真冒充实车。

总监收口共享接口与准确提交，专业执行者只改授权路径；用户每次一个主现场包，最多一个独立备用项。同一相机/板卡只由一个人操作。以上是分工顺序，不等于已经唤醒三个聊天；实际派发/接收在Issue登记。

## 1. 目标、依据与不可省略项

保持两线道路/曲线、普通线自主找位、随机可行起点/朝向、起步车位不可见、倒车入库、独立出库和跨场地。绕障仍后置；不改成标记定位、手输起点/车位或固定时长动作。固定可见车位是中间关，不是最终交付。

依据：用户2026-10-14关于年底期限、尽量提速和制定完整协作执行计划的要求；main基线`ef79e7713c698b1b60871b10ad4d811d9990401a`；[PROJECT_CONTEXT](../../PROJECT_CONTEXT.md)、[总体计划§5](../../00_project_master_plan.md#5-执行依赖与提速办法)和现有五专业附录。协作采用[团队指南v0.3.0](https://github.com/Sisu-z/project-team-playbook/blob/286bdec328cde8d7593a08308ea47d794ef081da/START_HERE.md)的总监、共享任务与审查规程。不是新一轮全网技术路线研究。

现有C/HAL、普通线候选、标定/回放、固定PythonRobotics规划和出库仿真可以作为起点；真实双轮闭环、视野/定位、搜索和实车泊车仍未验收。使用前执行者须复跑其改动涉及的基线，不把历史通过当本轮通过。硬件事实仍只从01及对应原始定位取值。

## 2. 你最先做什么：首个2小时现场包

这是启动后的首个低风险信息包，不是通电指令。没有清晰标签就记“看不到”，不拆电池、不拆电机、不强行掰舵机连杆。

| 顺序/预算 | 你的动作 | Agent收到后要交付什么 |
|---|---|---|
| 0～15分钟 | 把车、现有板件、电池/适配器、相机和连接线放在便于辨认的位置；确认车辆动力断开。已有6张照片无需重拍 | 总监对照库存，只列真正还缺的证据 |
| 15～40分钟（按余项缩短） | 现有四张商品图与S20F型号已登记，不重复整套拍摄；仅补驱动板角部版本号，具体无法匹配的电源接口/版本由总监点名后补；相机标签顺手可见则拍 | 电气负责人先消化已有来源，列“可确认/需测/暂不能接入”，提出明确接线和补件候选，不让用户猜规格 |
| 40～65分钟 | 断电量车身外廓长宽、前后轮轴中心距离、轮胎外径；注明测量位置，不必推导任何运动学公式 | 机械/算法建立尺寸配置候选、指出缺项；控制准备轮位/方向确认表。静态尺寸不等于实际转弯半径 |
| 65～105分钟 | 现有USB相机若可在电脑上直接取图，记录安装高度/朝向和原始画面：普通线正面、斜看、近处、无车位地砖/反光。先保持车辆不动；可移动相机模拟候选观察位置 | 系统提供可回放原帧与采集记录；算法给候选叠图和盲区/误检结论。手机照片只能补现场信息，不能替代本车相机证据 |
| 最后15分钟 | 告诉总监哪些项完成、哪些卡住、原始文件在哪里；不用再报精确日程 | 总监整理记录并给下一包，不要求用户填工程表格 |

相机需要新安装、权限或不能识别时停止该分项，先交标签/尺寸；系统负责人处理取流准备，不让你反复插拔试错。相机及电脑连接按实际设备条件；本包不接电机、不把未经核验的电池接X5、不强行测转向极限。图像默认留本地受控目录，公开Git只放去隐私的结论、标识和已批准样例。

**为什么它排第一：** 它同时决定电气测量怎么做、代码填哪些参数、摄像头能看什么、是否需要补件；比先读长教程或先优化PID更能解除依赖。下一步才是按审核方案固定可搬运总成并集中进行实验室测量。

## 4. 工作怎样并行，又在哪里必须汇合

```text
身份/断电信息 → P0分项电气准入 → P4单轮→双轮/转向/地面停稳 ─┐
现有相机原帧 → P3采集回放 → P6静态道路/车位/视野 ─────────┼→ P5基础链路/局部估计
模拟输入/已有库 → P1路径约束 → P2任务逻辑 ─────────────────┘       ↓
                   P6动态跟踪 ← 已接受的P5子产物 → P7可见位倒库/出库
                                                          ↓
                                                起步不可见主动找位
                                                          ↓
                                                P8独立场地/故障验收
```

图是功能依赖，不是要求P5整包等P6整包：P5协议替身与监督可先做；基础传播先消费P4里程，普通线修正消费P6静态观测，P6动态关联再消费已接受的估计。停止/电气门按对应负载单独放行，保留00§5.4已审的交叉关卡，避免循环等待。

| 包 | 牵头/能先复用什么 | 开始与交接条件 | 接受证据及主要阻塞去向 |
|---|---|---|---|
| P0 实物与台架 | 电气；01、现有板/工具、已审E0～E5 | 身份核对先做；通电待对应分项图纸/测点/保护审查及授权 | 可检查接线、测点、允许接入范围；身份/电平未知只阻塞相关接入，不阻塞录像/软件 |
| P1 路径约束 | 算法；既有RS/Pure Pursuit适配与测试 | 显式模拟尺寸/空间即可；不得写入实机配置 | 正反例覆盖入口方向、扫掠/未知域、换向连接；失败不交真实控制 |
| P2 任务状态 | 算法、系统审查；现有测试框架 | 状态/观测/执行契约草案先收敛；规划接P1接受版本 | PARK/EXIT/CANCEL、重复搜索/超时、停止确认可复现；模拟通过只解除逻辑依赖 |
| P3 数据与RDK | 系统；既有媒体/标定工具、兼容官方取流基础 | 电脑静态采集不等底盘；X5独立供电需对应审查 | 原帧/安装/时间/配置可追溯，断帧旧帧可诊断；X5受阻先做电脑回放，但保持板上待验 |
| P4 可控底盘 | 控制；现有C/HAL/单轮候选 | host部分可先做；实际信号/单轮/双轮按F门与E门逐项满足 | raw→CPR/dt→RPM→P/PI、双路/舵机及实测停稳/转向包络；电流/方向异常退回禁能 |
| P5 链路/估计 | 系统牵头、控制/算法消费 | 协议替身先做；真实传输、里程和观察按子产物接入 | 旧包/断线/重启拒绝，估计/帧龄有效性、独立监督；未证停止不准放行自主运动 |
| P6 感知 | 算法；现有OpenCV候选/投影/回放 | 静态等P3真实样本，不等P4；运动关联等P5有效反馈 | 普通线/地砖负例、尺度/入口、曲线和失效拒绝；视野不足触发安装/增补候选，不盲调算法 |
| P7 完整功能 | 总监组织集成、算法牵头 | P1～P6相关子产物满足运动条件，先M4后M5 | 多起点可见位倒库/出库→不可见位主动找位；固定起点成功不能算全功能 |
| P8 交付 | 用户现场、总监组织、独立审查 | 完整链重复稳定；验收场景/配置/指标事前冻结 | 另场地、完整任务和负例全部留记录；接管/拒绝/日志缺失不当成功，失败不删分母 |

每包开始前的正式Issue补齐：准确输入版本、可改路径、唯一执行者/run_id、预计下一次检查点、验收命令/证据、不得执行的动作。工作包表不复制任务实时状态。

## 5. 前两周的优先顺序：按测试轮次，不按日期打卡

用户明确不需要固定几点或哪天到场，因此按“上一轮证据接受→发下一轮包”推进。每轮是工作单元，不一定一天完成；数据充分时可以合并，出问题则拆分复测。下面时长是单轮安排预算，不是保证一次成功。等待批准/配件时切独立备用项，不赶表跳关。

| 轮次/本人预算 | 你的主动作 | Agent应先准备、再交付什么 |
|---|---|---|
| 1，约2h | 执行§2身份/尺寸/原帧信息包；手边没有的东西只登记，不因此等齐全部零件 | 总监整理输入；电气核精确资料，系统准备已有相机取流，算法复核基线和P1/P2规格 |
| 2，约3～4h | 图已审则做断电固定/标号；同时完成可独立进行的相机标定采样、道路/车位/地砖负例 | 电气给候选接线/测点与必要配件；系统给采集回放入口；算法给首批误检/视野分析 |
| 3，约3～4h，实验室 | 已具条件和授权后测无执行器供电轨、隔离波形及可接入信号；不先接整车试跑 | 电气/控制/独立Reviewer先审对应E0～E2步骤和回退版本；现场结果按分项接受，不笼统放行整车 |
| 4，约3～4h | 对已放行单轮做有界开环、原始编码器计数/方向及多圈测量 | 控制交准确候选、计数/方向表和日志；系统/算法继续替身及实拍回放 |
| 5，约3～4h | CPR与时基证据齐后测RPM、P→PI及停机/故障；不凭假参数调环 | 控制计算参数与分析曲线，Reviewer审比例/时基/故障；总监发有限的下一次试验，不让用户推导PID |
| 6，约3～4h起 | 另一电机按同样关卡验证，随后处理转向/双轮；不因第一台成功跳过另一台 | 控制复用单轮结果、实例化双路并处理共用安全/定时器；电气/机械审联合边界 |
| 并行支线，约3～4h | 可独立安全供电时做X5取流/静态性能/通信测试；可以插在第2～6轮之间 | 系统先处理环境兼容和记录，交板上实测；不把电脑通过当X5通过 |
| 汇合轮，约4～6h，可分两段 | 相应条件齐后测联合负载、低速地面停稳/转向包络；否则补集中仪器检查 | 总监收真实配置/可用域，组织影子运行和下一阶段最小闭环；原始失败留存 |

首10天左右做一次风险复核：电气适配、观察覆盖、机动空间能否支持主线，缺什么证据、是否需局部补件。这个节点用于暴露延期，不因日期到了就宣称通过。软件准备/测试应与这些轮次穿插；如果某包尚未准备好，只让用户做独立备用项或休息。

工作日可用3～4h，建议一次主测试加少量整理；周末如需8h，拆成两个3～4h时段并休息，优先集中仪器/整车测试，不连续疲劳接线。实验室有可安排半天是用户已确认条件，实际工位/仪器仍在使用前核验，不再追问精确日程。

## 6. 后续排期与周投入

用户现有时间容量足以支持较密集的现场反馈，但实际速度还取决于配件/Agent准备与实测结果。因此不再次仅凭可用工时把估计压低；以8～10周可交付作为条件目标，争取12月中旬完成。年底确切验收日尚未给出，不能把12/31当已确认的最晚时刻。下面仅给阶段窗口，不预约具体日期。

| 顺序/参考窗口 | 退出结果，不是仅交代码 | 人与Agent的重点 |
|---|---|---|
| 启动后前10天左右，早期判别 | 电气身份/适配、静态覆盖、底盘尺寸有证据与缺口；必要采购有明确决定路径 | 人取得输入；Agent交首批可测候选/回放，不等待所有硬件齐备 |
| 第2～3周左右，底盘与最小链路 | 对应E/F门通过；真实低速控制、道路观测和有界命令接通，开始循迹/弯道 | 有效联调周约25～30h；系统/算法先影子运行，准入后再驱动车辆 |
| 第4～5周左右，可见位闭环 | 多起点倒库与独立出库可重复；搜索逻辑已用替身/记录验证 | Agent日常用失败录像和日志改进；人做区分性复测，不重复无效动作 |
| 第6～7周左右，完整任务 | 起步不可见搜索→泊入→独立出库接通；至少一次非最终验收的异地试跑 | 不主动增加功能，优先完整任务稳定性；难题是否拖期要明确 |
| 第8～9周左右，交付验证 | 固定版本在独立场景复验，全部试验留记录，交可重复启动/演示包 | 工作量依重复试验表安排；Reviewer审证据，不只看成功视频 |
| 目标交付后至实际截止，约1～2周缓冲 | 只做必要补救、回归、搬运复装和最终交付 | 不再新增传感架构/大框架；任何实质改动按影响复验 |

用户容量按工作日3～4h、必要时周末2×8h计算，峰值约31～36h/周；这不是长期排满的承诺。建议高强度联调周约25～30h，资料/配件等待和Agent分析阶段降低现场投入；原140～180h个人工作量估计暂作粗预算，不因可用时间增加就宣称工作量变少，首轮实测后重估。普通采购3～4天/次按用户报告规划，争取前两周识别首批和视野补件，等待时跑独立软件任务；预留一次补件。不是承诺每家商家、定制件都3～4天，也不能把尾部缓冲重复分配给每个风险。

每轮由总监记录主要阻塞、剩余缓冲和下一项，阶段复核再估交付窗口，不给假百分比。前10天仍未解决关键电气、视野或空间假设，第3周仍没有可控底盘/有效观测，或第7周仍缺完整流程时，主动报告关键路径与替代，不继续沿用原估计假装正常。临时少一周投入优先消耗缓冲；连续下降则重估，不把数周工作压到最后周末。

## 7. 每轮协作闭环：让现场时间花在验证上

### 7.1 总监发包前的准备责任

测试包必须在用户开始该轮操作前准备好：输入/依赖已审；候选编译或电脑测试已跑；所需器件、工具、步骤和回退条件明确。无法提前准备就主动改为独立备用项，不让用户先接电等待。常规包控制为1～3个有明确判断目的的小试验。

包里只放六项：**目的；所需物品和允许接入范围；准确候选/配置版本；操作步骤与预期观察；停止/回退条件；需要回传的最少数据。** 具体电压、电流、测点和限位来自已审电气/控制包，本附录不另编数值。每包绑定Issue/run_id、固件/代码、接线/相机安装版本；版本不符先核对。

### 7.2 用户现场与最小回传

按包操作、监督和记录；不要求现场推导原因。紧急异常先按包的现实断能方式停止，不等聊天回复。日志/录像尽量由程序生成。

你只需说明：做的是哪一包、进行到哪一步、看到什么异常、原始文件在哪里。可以语音/短文字，Agent负责整理；可用条件发生变化时补一句即可，不要求精确日程。先保留异常原始记录，不仅上传挑选后的成功截图；原视频/设备日志不自动公开。

### 7.3 Agent分析、Reviewer和总监接受

执行者回填准确改动、来源、测试/未测、失败证据及下一项可区分验证。Reviewer检查自己负责的风险；总监核产物后接受为“可电脑测试/可申请台架验证/对应实物关卡已通过”等具体状态。PR合并不自动允许设备运动。

被接受上游的提交、配置变化和影响范围由总监通知下游；下游回填接收版本。未确认接收不写“已同步”，不让用户转发。不用向全部聊天广播所有日志。

## 8. 防冲突、额度与接手规则

- GitHub Issues仍是唯一任务状态源，PR是候选，main是接受基线；本附录只有顺序/依赖，不复制动态看板。每任务唯一run_id/修订、准确可改路径；恢复和交付前核main及原Issue。
- 总监独占中央记录的集成写入；执行者独立分支/工作区，不改其他模块。实际权限未隔离时必须诚实说明，文字职责不是沙盒。
- 并行上限提案：主要开发任务不超过3个、待集成大改不超过1个、发给人的现场主包1个。待测/待审积压时先清队列，不继续多开窗口。长期等真实数据的Agent转做有独立价值的测试或正常结束，不反复轮询消耗额度。
- 同一STM32/RDK/串口一次只有一个已确认操作者；会话开始登记占用、结束交接。真实控制与录像回放分离，离线回放不连执行器。取流、标定或接线变化使依赖它的候选重新待审。
- 一般问题一次集中诊断或最多三次有依据的尝试仍无新证据，就记录复现、已排除项和影响，交总监选择替代/暂缓；安全门保持关闭。不要只报告“卡住”，也不能为了过测试降低断言。
- 开源依赖采用已审固定版本，保留许可；HAL/驱动、OpenCV、RS、已有VOFA+/回放能用则用。先复现基线，再改最小缺口；不为证明能力重写、不做无边界文献综述、不先造管理平台或完整3D仿真。
- 上游接口变化先提变更，由总监审影响并更新唯一契约；消费者可在明确的实验契约下用替身，不自行冻结正式协议。
- 换Agent时只给启动入口、当前Issue、接受提交/配置和一份最小失败证据；让它先复现旧结果，再继续改。不反复从聊天中重建项目。
- Git记录不是调度器。本轮未设自动化或后台监控；总监当前会话内可协调，休眠后需用户唤醒或另行授权调度。需要现实时段就预约一个有限调试窗口，不声称随时实时响应。

## 9. 重大变化、采购和未答问题

先由Agent调查、总监给“推荐方案/理由/增量费用/工期影响/不选后果”，再请用户判断。只有采购、不可逆加工、场地/核心功能变化、正式接口及重大返工才上升决策；常规可逆代码细节由总监负责。

| 触发 | 不应继续的做法 | 推荐决策顺序 |
|---|---|---|
| 驱动/电源不匹配 | 继续调PI、升限流硬试、为已有板投入无限时间 | 查明证据→比较局部成品替代/保护适配→用户批准→只重测受影响E/F门 |
| 后/侧视盲区挡住任务 | 宣称里程计补全新障碍、盲走、默认四摄 | 调整可重复安装/观察动作→比较有限增补及整体接入代价→批准后采购；不因便宜而默认镜面/云台 |
| 日常空间机动不足 | 先下单地图、缩小仿真车身、暗缩随机起点 | 实测包络/局部路线→可调整临时布局→必要场地/硬件取舍交用户 |
| 几何视觉或RS真实失败 | 全面换模型/框架但不保留失败样本 | 复现错误→最小适配→有证据再评学习模型或局部搜索；同一数据/约束对照 |
| 后期课程/个人事务占用 | 保留不可能的排期、同时催用户多个包 | 总监降低在制量，软件继续；优先一次性高信息量采样/集中测试，重新计算缓冲 |

用户未及时回答时只暂停相关决定；问题合并到[OPEN_QUESTIONS](../../OPEN_QUESTIONS.md)，不重复发问。已经提供的工具、地面、照片、预算、核心功能和本轮可用时间/实验室半天不重问，也不要求继续提供精确日程。现阶段只需首包补齐现有件与样本；年底确切验收日如后续明确，再由总监校准缓冲，不阻塞独立工作。

## 10. 怎样认定交付，而不是“做了很多”

总监在前10天左右给一次范围/时间风险复核；在M1～M3取得数据后提出误差、间隙、耗时和正常成功率目标，由用户复核，目标在最终验收前冻结。建议第3周结束前完成第一轮量化验收草案；测量不足明确缺口和负责人，不伪填厘米数。试验次数和场地可用性也在此时估算，避免12月才发现没有验收条件。

交付必须包含：可重复启动的准确版本/依赖/配置；实测接线/安装与标定；完整任务与出库记录；不同起点/朝向、起步不可见和独立场地证据；故障/拒绝/接管记录；一页操作与恢复说明。原始数据仍留受控位置，公开只发已批准的脱敏证据。

完整任务、普通循迹/曲线、独立出库及安全负例分别验收；拒绝不算泊车成功，失日志不删分母。异地开发试跑不能冒充最终未参与调参的验收场景；若据结果改算法，该批数据归开发，另留独立验收条件。PPT、仿真和成功剪辑均不能替代这些证据。

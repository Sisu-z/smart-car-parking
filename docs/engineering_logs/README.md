# Engineering Logs

按时间记录实际学习、调试和装配。日志保留事件发生时的状态；最新硬件事实、接口与下一步仍以根目录的现行真源文档为准。

## 工程日志与个人复盘的用途

| 用途 | 写法与交付位置 |
|---|---|
| 工程日志 | 写入本目录并在下方索引。客观记录日期、事实与来源、当时状态、变更、已验证及验证范围、未验证项、问题和下一步。区分用户报告、实际测量和推断；避免大量主观感受与教学口吻。 |
| 个人复盘笔记 | 在聊天中发给用户，突出当时的感受、踩坑、原因分析、学到的经验、可复用的方法和下次怎么做，方便复习与学习。主观判断应标明是感受或推断，不写成已验证的工程事实。 |

两份内容可以来自同一次事件，文字不要求一致，但关键事实和验证状态必须一致。**仓库工程日志是该事件工程记录的项目真源；聊天中的个人复盘不是判断项目工程状态的依据。**历史日志是当时的记录，不自动覆盖根目录的现行真源文档。

以后用户说“总结”或“复盘”，默认按两种用途交付：GitHub 写标准工程日志，聊天发个人复盘笔记；用户明确限定只要一种时，按其要求。已有日志保留原来的阶段记录；后续新增或修订日志按本规范处理。
